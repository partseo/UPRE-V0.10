# DIR-0003 — PHASE 0C VISUAL PROGRAM EDITOR PROOF

COMMAND_ID: DIR-0003
PROJECT: UPRE-V0.10
PHASE: PHASE-0C
SCOPE: Sample Program Model → human-readable visual map → semantic edit → Working Model revision proof only
STATUS: READY

## 목적

PHASE 0B에서 확정한 Program Model을 실제 사람이 눈으로 이해하고 수정할 수 있음을 가장 작은 Vertical Slice로 증명한다.

이번 Slice는 실제 URL/프로그램 분석이 아니라 `fixtures/sample-program-model.json`만 사용한다.

핵심 흐름:

```text
Sample Program Model
  → Visual Projection Adapter
  → Understand View
  → Edit View
  → Model Command
  → Working Model Revision
  → Diff / Export
```

Visual Editor의 node/edge/position/viewport 상태는 Core Program Model에 저장하지 않는다.

## 구현 범위

### 1. Visual Proof App

`app/visual-proof/`에 최소 로컬 웹앱을 구현한다.

- React 기반
- React Flow (`@xyflow/react`) 사용 가능
- 사용 버전은 exact pin + lockfile 고정
- 불필요한 UI framework 추가 금지

화면은 최소 다음 4영역으로 구성한다.

1. 상단 Intent/Mode Bar
2. 중앙 Program Map
3. 우측 Inspector
4. 하단 또는 측면 Change/Attention Panel

### 2. Understand View

기본은 읽기 전용이다.

반드시 표시:

- Screen
- Component
- Action
- Behavior
- Flow
- DataEntity
- LogicRule
- ProtectedAsset
- OSSReference
- typed Relation

Node 또는 Relation 선택 시 Inspector에 최소 표시:

- ID / Type / Name
- Truth Classification
- Confidence
- Verification Status
- Evidence reference
- Provenance

OBSERVED / DERIVED / INFERRED / USER_VERIFIED / CONFLICT가 시각적으로 구분되어야 한다.

### 3. Visual Projection Adapter

Core Model을 직접 React Flow 구조로 바꾸어 저장하지 않는다.

최소 경계:

```text
Program Model Snapshot
  → Visual Projection Adapter
  → adapter-owned nodes / edges / positions
```

Projection은 deterministic 해야 한다.

같은 fixture를 두 번 Projection하면 semantic node/edge identity와 기본 layout 결과가 동일해야 한다.

### 4. Edit View

Edit Mode에서 최소 두 종류의 의미 편집을 지원한다.

A. Entity Rename
B. Move To Warehouse / Restore

사용자 작업은 반드시:

```text
Visual Event
  → Model Command
  → Working Model Revision
```

경로로 처리한다.

Canvas state를 직접 Core JSON에 쓰지 않는다.

### 5. Original / Working 분리

화면에서 최소 다음을 확인할 수 있어야 한다.

- ORIGINAL_MODEL
- WORKING_MODEL

Rename 또는 Warehouse 이동 후에도 ORIGINAL_MODEL 값은 변하지 않아야 한다.

Working Revision에는 변경 이유와 command identity가 추적 가능해야 한다.

### 6. Change Panel

편집 후 최소 다음을 보여준다.

- Added
- Removed / Warehoused
- Changed
- User Verified change

Before / After 값을 사람이 읽을 수 있게 표시한다.

### 7. Export

현재 Working Model을 JSON으로 Export할 수 있어야 한다.

Export 결과는 기존 Program Model validation을 통과해야 한다.

Visual 전용 필드가 Export된 Core Model에 포함되면 FAIL이다.

## 범위 제한

이번 Slice에서 실제 사이트/앱을 분석하지 않는다.

Archify Runtime 통합은 하지 않는다. Archify는 다음 Understand Projection 확장 후보로 유지한다.

Program Model Core Schema는 Visual 편의를 위해 변경하지 않는다. 정말 불가피하면 작업을 중단하고 HUMAN_REQUIRED로 보고한다.
